How GLB Viewer Works

A plain-English walkthrough of what actually happens when you drop a .glb or .gltf file onto the page — and why nothing about that process ever touches a server.

1. Your file never leaves your browser

When you drag a file onto the page or pick one from the file dialog, the browser hands GLB Viewer a local File object. The tool reads it with file.arrayBuffer() and creates a local blob URL via URL.createObjectURL() — both are built-in browser APIs that operate purely in memory. There is no upload step, no backend, and no network request involving your model's contents at any point.

2. Reading the stats directly from the binary container

A .glb file is a binary container: a short header followed by a JSON chunk (the glTF scene description — nodes, meshes, materials, textures) and a binary chunk (the actual vertex/index/image data). GLB Viewer parses that JSON chunk directly to compute:

  • Triangle count, and mesh / primitive / material / node counts
  • Per-texture dimensions and byte size, and texture share of total file size
  • Which glTF extensionsUsed the file relies on — flagging Draco, Meshopt, WebP, and KTX2 specifically
  • The exporting tool's asset.generator string, when present

This is hand-rolled parsing rather than a general-purpose glTF library, on purpose — it keeps the tool dependency-free and means the stats panel reflects exactly what's in the file, not an interpretation of it.

3. Rendering with <model-viewer>

Once the stats are read, the same local blob URL is handed to <model-viewer>, Google's web component for displaying 3D models via WebGL. It's loaded from a self-hosted copy bundled with this site rather than a CDN, so rendering keeps working even with no network access after the first page load.

4. Decoding Draco-compressed geometry locally

Files that use KHR_draco_mesh_compression to shrink mesh geometry are decoded by a self-hosted Draco decoder (WebAssembly + JS glue), also bundled with the site. No round-trip to Google's CDN is needed to decompress a Draco model.

5. Comparing two models side by side

Drop or pick two files at once — or drag a second file directly onto the right-hand viewport once one model is already loaded — to open both side by side. Their cameras (orbit, target, and field of view) stay in sync: drag either viewport and the other follows, so it's easy to compare geometry, texture quality, or compression settings before/after an export change. The stats panel also shows the size, triangle, and texture deltas between the two.
